# Minimal Linux

[![Build](https://github.com/asapelkin/asdasdasd/actions/workflows/build.yml/badge.svg)](https://github.com/asapelkin/asdasdasd/actions/workflows/build.yml)

A minimal Linux distribution based on **Ubuntu 24.04** (Noble Numbat) with
**Python** and **LLVM** compiled from source, orchestrated by
[BuildStream](https://buildstream.build/).

## What's included

| Component | Version | Build method |
|-----------|---------|-------------|
| Base OS   | Ubuntu 24.04 | `debootstrap --variant=minbase` |
| Build SDK | Ubuntu 24.04 + dev tools | `debootstrap --variant=buildd` |
| Python    | 3.12.x  | Compiled from CPython git source |
| LLVM      | 18.1.x  | Compiled from llvm-project git source |
| Wheelhouse | PyPI package sources | Fetched by BuildStream pip source |

## Project layout

```
project.conf             BuildStream project configuration
project.refs             Source refs (git SHA / sha256) – updated by scripts
elements/
  base/
    ubuntu.bst           Ubuntu 24.04 minimal base (runtime, local source)
    sdk.bst              Ubuntu 24.04 SDK with build tools (local source)
  components/
    python3.bst          CPython 3.12 – autotools build against sdk.bst
    llvm.bst             LLVM 18.1 – CMake build against sdk.bst
    wheelhouse.bst       PyPI source wheelhouse for pytest/click/tabulate/numpy
  image/
    system.bst           Final image: ubuntu + python3 + llvm (stack)
scripts/
  create-sdk.sh          Create files/ubuntu-base/ and files/sdk/ via debootstrap
Makefile                 Convenience build targets
.github/workflows/
  build.yml              CI: build on every push / pull request
  release.yml            CD: build and publish on version tag (v*)
```

> **Note – `files/` directory**: `files/ubuntu-base/` and `files/sdk/` are
> generated by `scripts/create-sdk.sh` using `debootstrap`. They are listed
> in `.gitignore` and must be recreated before each build.

## Building locally

### Prerequisites

```bash
# Ubuntu 24.04
sudo apt-get install -y python3-pip bubblewrap debootstrap
pip install 'BuildStream>=2.0' buildstream-plugins ruamel.yaml
```

### 1 – Create the Ubuntu base and SDK rootfs

```bash
sudo bash scripts/create-sdk.sh
sudo chown -R "$USER:$USER" files/
```

This uses `debootstrap` to create two Ubuntu 24.04 root filesystems:

- `files/ubuntu-base/` — minimal rootfs for the runtime image
- `files/sdk/` — rootfs with build tools (`build-essential`, `libssl-dev`,
  `libffi-dev`, `cmake`, `meson`, `ninja-build`, etc.)

### 2 – Populate source refs

```bash
# Refresh the exact refs stored in project.refs
bst source track components/python3.bst components/llvm.bst components/wheelhouse.bst
```

Committed `project.refs` entries are already included in the repository, so
normal builds do not need this step unless you want to update source versions.

### 3 – Build

```bash
bst build image/system.bst
```

The first build compiles Python and LLVM from source inside BuildStream's
isolated sandbox (powered by bubblewrap), and fetches the Python package
wheelhouse through BuildStream source tracking. Subsequent builds reuse the
artifact cache and are nearly instant.

### 4 – Check out the image

```bash
mkdir -p output
bst artifact checkout image/system.bst --directory output/
tar -czf minimal-linux.tar.gz -C output .
```

You can also use the Makefile shortcuts:

```bash
make all      # installs missing prerequisites, then runs steps 1-4
make build    # build only
make wheelhouse # build and export just the Python package wheelhouse
make checkout # export image to output/
make clean    # remove output/
```

## CI / CD (GitHub Actions)

| Workflow | Trigger | Action |
|----------|---------|--------|
| `build.yml`   | push / PR to `main` | Build the image, upload artifact |
| `release.yml` | push of a `v*` tag  | Build, then publish a GitHub Release |

### Creating a release

```bash
git tag v1.0.0
git push origin v1.0.0
```

The release workflow will:
1. Build the complete system image using BuildStream
2. Create a `minimal-linux-v1.0.0.tar.gz` archive
3. Publish it as a [GitHub Release](../../releases) with a SHA-256 checksum file

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                   elements/image/system.bst                      │
│                       (stack element)                             │
│                                                                   │
│  ┌──────────────────┐  ┌────────────────┐  ┌────────────────┐   │
│  │  base/ubuntu     │  │ components/    │  │ components/    │   │
│  │  Ubuntu 24.04    │  │ python3        │  │ llvm           │   │
│  │  minimal rootfs  │  │ CPython 3.12   │  │ LLVM 18.1      │   │
│  │  (runtime base)  │  │ from source    │  │ from source    │   │
│  └──────────────────┘  └───────┬────────┘  └───────┬────────┘   │
│                                │ build-dep         │ build-dep   │
│                         ┌──────▼──────────────────────────┐       │
│                         │         base/sdk                 │       │
│                         │  Ubuntu 24.04 + build tools      │       │
│                         │  (GCC, cmake, meson, ninja…)     │       │
│                         └──────────────────────────────────┘       │
└─────────────────────────────────────────────────────────────────┘
```

**Build flow**:
1. `base/sdk.bst` imports the Ubuntu 24.04 SDK rootfs as the build environment
2. `components/python3.bst` compiles CPython inside the SDK sandbox
3. `components/llvm.bst` compiles LLVM inside the SDK sandbox
4. `components/wheelhouse.bst` fetches pytest, click, tabulate, numpy and all transitive Python package sources
5. `image/system.bst` merges the Ubuntu base + Python + LLVM + wheelhouse into one image
